# CLOUD-03.2A — Ensayo transaccional de revisiones
El archivo SQL de tests se ejecuta íntegramente en una transacción que termina en ROLLBACK. Requiere Postgres con roles anon/authenticated (Supabase) y usuario administrador; no ejecutar fragmentos por separado ni convertirlo en una migración. Usa bytes sintéticos, no claves ni imágenes. El esquema de laboratorio es privado, RLS activo, no hay permisos de clientes ni funciones SECURITY DEFINER.

## Decisiones
Se conserva historial inmutable por (archivo, recuerdo, revisión); un recibo por (archivo, operación) queda en la misma fila. El lock de la fila del archivo serializa publicaciones (coarse-grained para dos usuarios). Se compara revisión esperada y se exige el conjunto completo de activos staged de esa operación, revisión y tamaño. El reintento compara metadatos cifrados, nonce y conjunto de IDs. El ensayo supone staging inmutable y no expone una API de staging. No verifica la autenticidad AES-GCM en servidor: el cliente ya verifica manifiesto y hash en CLOUD-03.1. El servidor no tiene clave. Los bytes de staging son un sustituto de Storage únicamente para probar atomicidad. El ensayo no certifica simultaneidad entre conexiones reales, idempotencia de uploads ni seguridad de una API pública.

## Siguiente diseño de Storage
Ruta opaca e inmutable archive UUID/operation UUID/asset UUID; ninguna parte incluye título/MIME original. Upload create-only, sin upsert; registrar intención y recibo por activo con longitud/hash de ciphertext verificados por un servicio de confianza. No confiar en metadata enviada por cliente como prueba de integridad. Confirmar revisión dentro de transacción sólo con todos los recibos y pertenencia, comprobar versión de clave; no borrar blobs referenciados, reconciliar staging huérfano con período de gracia. Lectura privada por membresía y objeto publicado; sin URLs públicas. Resolver carreras entre staging, commit y limpieza antes de habilitar Storage. Autorización por auth.uid(), no user_metadata. No implementar acceso real hasta aprobar tercero negativo y custodia. La cola local persistente, revisión UI y pruebas de caída siguen pendientes.

## Ejecución y alcance
tests/sql/cloud_03_2_transaction_lab.sql contiene DDL y assertions, con rollback final. No registra migración ni toca public.archives, memories o storage. El archivo se entrega como ensayo reproducible, no como aplicación automática. CI del frontend independiente.
