# CLOUD-03.3B — núcleo del servicio remoto
El servidor valida exactamente el contrato de #26, sesión verificada, membresía, huella, activación de laboratorio, límites y rutas opacas. Antes de commit consulta intención inmutable y lee los bytes desde Storage mediante un adaptador de confianza. Compara SHA-256 y longitud independientemente del cliente, revalida membresía antes de confirmar. Sin logs de cuerpos ni claves. Cinco pruebas con dependencias simuladas.
No es una Edge Function desplegable aún: faltan adaptadores reales de verificación de token, base transaccional y descarga; deben revalidar autorización dentro de la transacción, guardar intención canónica, proteger rutas contra borrado/reemplazo y aplicar cuotas. El servidor no puede distinguir por criptografía un recuerdo real de uno ficticio; la UI de laboratorio debe generar sólo muestras. La huella no demuestra posesión de la clave al servidor. Sin Storage ni INSERT remotos habilitados. No se envían secretos al servidor.
Política propuesta: bucket privado separado; INSERT sólo por miembro propietario de intención exacta activa, SELECT sólo de intención propia o revisión confirmada del archivo; no UPDATE ni DELETE cliente. Probar tercero, anónimo, acceso cruzado, cambios de membresía y revocación; usar grants mínimos y RLS. Antes de desplegar faltan pruebas reales y adaptadores transaccionales. No usar la base real para ensayos de escritura persistente.
