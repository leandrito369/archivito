# CLOUD-03.4B — Identidad y reconciliación v3
Corte aislado, sin red/UI ni modificación de la biblioteca. El mapa IndexedDB archivito-sync-v3-identity-v1 vincula localId (incluidos legados) a remote UUID de forma 1:1 por usuario/archivo. Clave de índice única; asignación transaccional; nunca remapea automáticamente. La clave criptográfica no forma parte de la identidad para permitir futura rotación controlada. Aislamiento lógico, no frontera de autorización; no confiar en IDB como prueba de identidad. Al importar se deberá elegir ID local y reservar vínculo en operación recuperable; no unir dos copias sin confirmación.

Reconciliación pura: base conocida revision/operationId + baseGeneration; estado local por generation UUID, remoto por revision/operationId. Si sólo cambia local -> publish CAS; si sólo remoto -> pull condicionado a generación; si ambos -> conflicto sin merge ni sobreescritura; si remoto retrocede o cambia operación en misma revisión -> bloquear; falta local conocida -> bloquear, nunca inferir borrado. Generación debe cambiar atómicamente con cada edición real (pendiente); no usar timestamps. Recibo confirma generación codificada, no edición posterior. Los adaptadores deberán persistir baseline y aplicar pull con CAS atómico o diario de recuperación junto a la biblioteca. Este módulo sólo decide, no aplica ni guarda revisiones locales.

Simulador v3 conserva historial y recibos, mismo ciphertext para replay, CAS y conflicto, rechaza cambio de clave; no sustituye autorización, transacción real, cuota o retención. Cinco pruebas Node con v3 y dos pruebas Chromium de mapa persistente. No se incluye en dist. No usa backend fixture ni gate de laboratorio. Pendientes: cola v3 durable con límites de memoria/Storage, baseline y escritura atómica con biblioteca, transporte real diferenciado, validación de imágenes, E2E edición con sesiones reales, tercero y custodia definitiva.
