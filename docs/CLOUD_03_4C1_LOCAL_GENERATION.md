# CLOUD-03.4C1 — Generación local atómica
Primer subcorte de integración con la biblioteca. Se mantiene IndexedDB nuestro-archivo-cartas-v1 / letters / versión 1. Campo local syncGeneration UUID v4 aleatorio, persistido junto al recuerdo en la misma transacción. Se renueva en cada put de editor/favorito, importación atómica (no confiar en generación importada), add de digitalización nueva y guardado de cara existente. Captura verifica updatedAt y generación de apertura antes de modificar. Sin migración al leer: registros históricos sin campo siguen válidos y se marcarán al editar. Backup v3 no exporta el campo (lista explícita), el codec tampoco. No usar timestamps para identificar generación. Si falla la transacción no se confirma cambio ni generación.
No hay subida, nueva cola v3 ni baseline todavía; este campo es el insumo durable para identificar cambios, no estado de sincronización. No se registran tombstones: borrar local no borra remoto y futura reconciliación debe bloquear si desaparece un vínculo conocido. No se añade UI de sync. Pestañas/versiones anteriores pueden escribir sin renovar generación; antes de habilitar reconciliación real se requiere cerrar clientes antiguos y establecer estrategia de detección (incluido hash de contenido/versiones). El editor y favoritos existentes aún no tienen CAS completo entre pestañas; no afirmar resolución de concurrencia local. No se modifica el esquema físico ni la base remota.
Pruebas: nuevas pruebas reales Chromium para generación, importación abortada y digitalización nueva, assertions de captura existente y respaldo. CI pendiente. Siguiente C2: baseline, snapshot cifrado de generación, cola v3 durable y aplicación CAS sin sobrescribir borradores.
