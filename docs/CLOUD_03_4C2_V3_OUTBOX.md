# CLOUD-03.4C2 — Outbox v3 persistente
Base independiente archivito-sync-v3-outbox-v1, stores heads/jobs/packets. Lectura readonly de letters y snapshot v3 con generación registrada; vinculación por mapa #31. No modifica la biblioteca, no crea DB histórica ausente, no migra registros sin generación. No UI ni red, no incluida en dist. prepareLocalV3 es entrada explícita del ensayo; prepara paquete cifrado y lo guarda de forma atómica con metadatos de operación. El ID local técnico queda visible localmente en job/head, no contenido en claro. Scope usuario/archivo, huella fija por vínculo activo; cambio de huella bloqueado, no rotación automática. Aislamiento lógico, no autenticación.
Un trabajo por recuerdo; CAS baseline al encolar y al confirmar. Reintento exacto con lease de 120s/token. Error conserva paquete; conflicto conserva paquete y no permite reintento automático. Recepción synced válida: baseline revision/operationId + generación codificada y eliminación del trabajo/paquete en la misma transacción. Edición posterior permanece distinta de baseline y se vuelve a preparar; no se consulta ni cambia el recuerdo durante la confirmación. Cuota provisional global 8 jobs/256 MiB de bytes de sobres, no cuota real del navegador. No cargar otros paquetes para sumar tamaños. No resolver conflictos ni aplicar pull, tampoco borrar remoto. No confiar en la respuesta de transporte hasta integrar autorización y autenticación real. El cliente aún no tiene guardas de sesiones reales aquí; jamás conectar directamente a red.
Pruebas Chromium: snapshot de biblioteca, confirmación y edición posterior, recarga y lease/retry exacto, conflicto retenido y separación lógica. No se certifica cuota física, IOS, concurrencia de versiones antiguas, importación remota ni atomicidad de pull.
