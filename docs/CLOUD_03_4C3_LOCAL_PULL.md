# CLOUD-03.4C3 — Aplicación local de revisiones entrantes
Corte offline no integrado en dist/UI. Decodifica paquete v3 completo, valida identidad, revisión, operación, clave y activos antes de tocar biblioteca. Importación requiere UUID local nuevo explícito; no usa ID local del manifiesto ni une registros por coincidencia. Mapa de identidad se reserva antes de escribir; si se interrumpe puede retomarse con el mismo vínculo. Pull sólo si generación local coincide con baseline y no hay trabajo saliente; conflicto, rollback, equivocation, ausencia de registro conocido o legado sin generación no sobrescriben.
Como IndexedDB no permite transacción entre bases distintas, diario pull en heads del outbox: reserva CAS de base/generación/huella de paquete y generación destino; bloquea prepare saliente; aplica en una transacción letters mediante CAS; finalmente actualiza baseline en outbox. Si se corta después de escribir letters, refetch del paquete exacto permite reconocer generación ya aplicada y finalizar sin repetir escritura. Si cambia el registro antes de completar, queda bloqueado conservadoramente; no se elimina diario automáticamente. No se almacena paquete entrante en diario; requiere conservar/refetch del exacto. No es atomicidad distribuida. No borra, no modifica remoto y no ofrece resolución de conflicto manual aún. El journal confía en generación emitida por escritores actuales, no protege de versiones antiguas que escriben sin renovarla; gate antes de producción. No usar sin autorización verificada y cabeza remota confiable, tampoco protege rollback malicioso que simula revisiones superiores. Los registros locales siguen siendo plaintext como antes.
Pruebas reales Chromium (import/pull, conflicto, interrupción de baseline y recuperación). Las imágenes son bytes sintéticos, validadores inyectados. No habilita sincronización de recuerdos reales ni modifica Supabase. Siguiente: backend v3 diferenciado, autorización/quotas/transferencia por partes, control de escritores antiguos y E2E bidireccional ficticio.
