# CLOUD-03.5B — Primera optimización medible
Base #40 CI verde. Modo referencia conserva guardas remotas por I/O y concurrencia 1; modo optimizado usa epoch local síncrono antes/después de I/O, fresh al comienzo, antes begin, después begin, después de cada lote y después commit. No autorización cacheada por TTL; server RPC y RLS sin cambio. Lectura sigue secuencial, fresh antes/tras consulta de cabecera y al final de reconstrucción, RLS en cada descarga, local epoch entre I/O. Cambio de sesión o lock invalida el epoch. No deshace requests ya aceptados. No modificar backend ni activar gate.
Subida de máximo dos bloques concurrentes por lote, allSettled garantiza que una falla no libera la cola mientras quedan requests activos; no commit si lote falla; lease original 120 s no renovado (idempotencia y token evitan duplicar confirmación, pendiente). Progreso verificado en bloques; no porcentaje de tiempo estimado. No cancelación de fetch en vuelo. 
Métricas locales sólo fase/count/ms/bytes, sin datos/ID/token, no telemetría remota. Sumas de fases se solapan (auth y reconstrucción, bloques concurrentes, total incluye todo); bytes de bloque son intentados, no confirmados, y no se contabiliza overhead HTTP. Snapshot/prepare incluyen IDB y cifrado, apply incluye descifrado/validación/CAS; no separar tiempos internos todavía. Comparación de referencia/optimizado en UI de lab; los 3 commits previos están protegidos y gate cerrado. Tests Node: peak=2, 5 fresh en dos bloques vs 13 con referencia (guardas comando + inicial), espera de requests ante fallo, epoch invalida commit; prueba session key. No medir mejora real sin nuevo ensayo separado, ni prometer tiempos. Próximo: benchmark sintético con 3 tamaños y distintas condiciones, percentiles, diseño incremental 03.5C (nuevo contrato AAD/retención/GC), control de lease y certificación móvil/tercero.
Benchmark automatizado adicional: 256 KiB, 4 MiB+2, 12 MiB+2; tres repeticiones por modo, mismo paquete por tamaño, retardos artificiales de 3ms/auth, 5ms begin/commit, 20ms/block, diagnósticos p50/máximo y conteos. Se comprueban concurrencia y número de verificaciones determinísticamente, no umbrales de tiempo; no representa Internet ni Supabase. La muestra de tres no permite estimar p95 robusto. El benchmark real sigue pendiente.
