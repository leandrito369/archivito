# CLOUD-03.5C3A2 — Wire incremental y laboratorio transaccional
Wire archivito-incremental-wire-v1 JSON con header autenticado (metadata base64url), base revision/operationId y uploads sólo de activos nacidos en la revisión. Bloques máximos 4 MiB, rutas archive/memory/asset/index independientes de operación, hashes de bloque y activo. Metadata-only uploads=[]; lectura reconstruye desde descriptor de nacimiento autorizado, verifica hashes y codec incremental verifica AES-GCM. La cabecera de nacimiento no debe desaparecer al podar revisión: persistir descriptor/chunks inmutables aparte; futuro adaptador resuelve referencias desde revisión confirmada y catálogo de activos. Sin red/UI/dist.
Laboratorio SQL BEGIN/ROLLBACK esquema privado con RLS y grants cerrados, lock gate por archivo, membresía/clave, intención actor+wire inmutable, reserva cabecera+activos nuevos, referencias por revisión, catálogo de activos, bloques y attestations simuladas, CAS revision/operationId, recibo idempotente. Prueba de metadata-only sin bloques adicionales, historial y reserva doble rechazada. SQL supone wire previamente validado estrictamente; JSON de test deliberadamente sintético, no prueba autenticidad criptográfica, Storage real, JWT ni concurrencia de conexiones independientes. Intención que pierde CAS conserva reserva y refs hasta fencing/GC, no se elimina automáticamente. No hay ejecución de retención o limpieza, no migración, no tocar gate v3. 
Pendientes C3B: esquema persistente cerrado con catálogo de descriptores independiente del manifiesto, locks/holds/fencing, autorización real, Storage API create-only/readback, outbox incremental durable y cache verificada, benchmark en red real y E2E. Cuota y GC reales aún no certificados. Cuatro pruebas Node wire, SQL reproducible.
