# CLOUD-03.5C3B1 — Candidato de esquema persistente cerrado

FK compuestas por archivo/memoria impiden referencias cruzadas, FK de heads/holds impiden borrar manifiestos protegidos estructuralmente, FK de refs impiden borrar activos referenciados. Rutas canónicas de bloques, índice máximo 8 para activo hasta 35 MiB+tag. Recibo de nacimiento permanece aunque se retire un manifiesto; el catálogo no depende de éste. Gate CHECK(not enabled) deliberadamente cerrado hasta migración revisada. RLS en 8 tablas, sin grants de schema ni tabla a cliente o service_role. No RPC ni bucket nuevo. No ejecutar como migración definitiva todavía.
Prueba estructural reversible: concatenar BEGIN; DDL candidato; test; ROLLBACK; en proyecto con un archivo y propietario. Utiliza IDs ficticios, no cambia datos existentes. Simula retirar manifiesto r1 exclusivamente para comprobar independencia referencial; NO autoriza podar primera revisión en producción. La política A1 deberá aplicarse en RPC privilegiada bajo lock, no por FK solamente. Falta verificar que cada head sea committed, estado activo/GC, contigüidad de bloques y hash de activo, validación exacta wire y permisos de servicio, reserva transaccional y cálculo de cuotas (receipt_bytes + charged_bytes + ciphertext_bytes; pendientes también), recibos/tombstones, holds/quiescencia, fencing, retención y Storage API. Sin purga ni benchmark, sin despliegue.
