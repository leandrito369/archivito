# CLOUD-03.5C3B2B — Servicio remoto y Storage incremental cerrado
Base #47 CI verde. Bucket privado nuevo, 4 MiB octet-stream, sin políticas cliente. RPC inspect invoker sólo service_role, gate/miembro/huella bajo lock, intent propietario exacto, head/revision committed, catalog requiere referencia committed y asset ready con nacimiento committed; descriptor/chunks independientes de manifiesto de nacimiento. Ensayo SQL rollback con filas sintéticas (no Storage físico). Edge candidata: POST CORS localhost8000, token getUser obligatorio, body bounded, RPC privilegiadas internas, create-only; block verifica bytes antes y después, readback recupera respuesta perdida, attest reconstruye activo completo y comprueba hash antes de RPC; no prueba aportada por cliente. Lectura proxy por catálogo, revalida sesión y referencia después de download; nunca URLs públicas. 5 tests mock. No apertura gate, no GC ni cambios v3. 
Limitaciones: readback completo hasta 35 MiB consume memoria y red adicional, no medir aún. Bloques stored no equivalen a activo attested; retry puede descargar antes de volver a subir. El servicio usa API privada con service_role; no acceso de cliente a schema, RPC ni bucket. JWT real/Storage positivo, concurrencia física, fencing/quiescencia y leases, GC/retención, cache, outbox y benchmark pendientes. No habilitar hasta aceptación acotada. No usar el esquema de v3 para migrar automáticamente.
