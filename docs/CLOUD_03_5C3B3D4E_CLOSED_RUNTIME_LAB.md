## Hallazgos y bloqueos de promoción
1. CRÍTICO: Edge candidato invoca sync_inc_cert_http ausente hoy; ACL candidata revoca EXECUTE legacy y USAGE/CRUD core de service_role que usa la Edge v1. No aplicar candidato en proyecto actual ni sustituir Edge de manera independiente. Requiere cutover/rollback coordinado y autorización específica.
2. ALTO: orden de locks descrito en D.2 window -> fence -> gate -> membership -> archive, pero dispatch.actor_guard toma window -> session -> membership -> archive antes de entrar core gate. El window serializa wrappers por archivo, no a administradores/legacy que bloquean gate primero. Revisar orden común y certificar deadlock/rollback frente a cierre, cambio de membresía, key rotation y logout. No se afirma deadlock observado. 
3. ALTO: el rol de servicio sigue BYPASSRLS y puede acceder a otras APIs de plataforma; sólo límite frente a acceso legacy y clientes, no frente a secret comprometido. dispatch recibe actor/session desde Edge confiable, no autentica JWT por sí mismo. Verificar grants efectivos por columna/roles/default privileges, owner NOLOGIN/NOBYPASSRLS, search_path, schema no expuesto, y ausencia de grants PUBLIC nuevos en stack local real. No mover credenciales de servicio fuera de servidor.
4. ALTO: auth.sessions y storage.objects son relaciones administradas; permisos de políticas, ownership, restricciones, triggers, FK y PostgREST schema cache no están reproducidos por PG desnudo. RLS preexistente compatible por nombre/columnas no equivale a DDL desplegable. Candidato usa grants amplios internos para tablas y locks con WITH CHECK false; auditar que no se pueda mutar filas de autorización. No aplicar sobre remoto.
5. MEDIO: Deno CLI no es Supabase Edge Runtime; imports relativos fuera de functions/ y resolución npm deben certificarse con empaquetador/runtime real. SDK pin exacto 2.119.2 existente en código; lock transitivo aún no incorporado, Deno 2.5.6 y postgres:17 en laboratorio no acreditan paridad exacta de imágenes.
6. Gate cerrado hace que actor_guard deniegue antes de sesión/membresía/fence: 403 no prueba causalidad de esos controles. Las pruebas positivas, stale fence y revocación se ejecutaron en D.2/D.3 en PG desechable con gate de prueba habilitado, NO en este corte. No usar ese resultado como autorización para apertura actual.
